## The layer-1 check has been observed failing, on the tree as it ships

`pnpm verify:layer1` is green here and has to be, or something is wrong. A check that is only
ever green is not evidence, so it has also been run against a **corrupted copy** of the
reference — one digest replaced by `deadbeef…`. The copy is a throwaway
(`verify-layer1.mjs` takes `LAYER1_REF`); `results/layer1-digests.txt` is never edited.

```
$ node tools/verify-layer1.mjs                                    # default tree, default reference
p1  MATCH     live=90a5e26c296287ca…  reference=90a5e26c296287ca…
p2  MATCH     p3  MATCH
checked 3 patterns, 0 mismatched                                  exit 0

$ LAYER1_REF=$T/corrupt.txt node tools/verify-layer1.mjs          # same tree, corrupted copy
p1  MISMATCH  live=90a5e26c296287ca…  reference=deadbeef296287ca…
p2  MATCH     p3  MATCH
checked 3 patterns, 1 mismatched                                  exit 1
```

The corruption was sighted before the red was believed — `diff` against the original shows the
one changed line — because an edit that changed nothing produces a green that reads exactly
like a working check. `pnpm controls`' `L1-SEM` arm is the stronger version of the same
requirement: there the *digests* move, not the reference, which is what shows they are
computed rather than copied. `results/layer1-strudel-126.md` runs both against 1.2.6.

## The batch column is derived, and asserted

The raw logs of runs A and B, and of the pool arm, record pid, position, digest and peak — but
not the batch. The protocol runs `WIDTH` processes concurrently and waits before starting the
next batch, so a batch is a contiguous block of `WIDTH × RENDERS` rows whose processes are
disjoint from every other batch's.

That is a derivation, so `tools/derive-batches.mjs` **asserts** it rather than assuming it:
every batch must contain exactly `WIDTH` distinct pids, each appearing exactly `RENDERS`
times, and no pid may appear in two batches. A log that does not satisfy this is rejected
instead of being given a batch column it has not earned. All three logs satisfy it exactly:
8 batches of 8 distinct pids, 3 rows each.

Runs 1 and 2 were written by the protocol script itself and carry the batch directly.

## `artefact-reproduce-192.txt` is evidence for a contrast, not an artefact of this repository

The ICLC paper contrasts Strudel's behaviour against its own frozen render artefact, which
reproduced 192/192 under this same protocol on the same host at comparable load. That
artefact is a **separate, separately cited object**. It is not vendored here, was not
modified by this study, and **nothing in this repository can regenerate that log.** It is
included so the contrast the paper draws is legible, and it is fenced off here so it is not
mistaken for something a reader of this repository can re-derive.

## Recounting anything

```sh
# divergent renders in a run, and how many distinct outputs
CANON=4f815a0c00b17a83c11339220cf578f25815de1d139f6e7b3b866c5d95fdf625
awk -F'\t' -v c=$CANON '$1 ~ /^[0-9]+$/ && $4 != c' measured/layer2-runA-192.tsv | wc -l   # -> 9
awk -F'\t' '$1 ~ /^[0-9]+$/ {print $4}' measured/layer2-runA-192.tsv | sort -u | wc -l     # -> 6

# or let the tool do it
node ../tools/summarise-run.mjs this-repo/layer2-run2-192.tsv
```
